# BulkReg – Changelog

All components carry the same release number: `VERSION`, both LotusScript libraries (`BR_VERSION` in BulkRegCommon, header of BulkRegAgents) and the header of every agent, `bulkreg.ini`, `server_mapping.csv`, the PowerShell helper, the Audit Viewer, the README and the Admin Guide (which reads `VERSION` when it is built). Check with `scripts\windows\bulkreg.cmd Versions`.

| Release | Guide | Date | Changes |
|---|---|---|---|
| **3.8.0** | 3.8.0 | 2026-10-06 | **Fixes and features from the first 3.7.0 live pilot.** (1) Compile fix: `List As Long` (was `List Long`) in BulkRegCommon and Preflight. (2) **Names:** Notes full name from `FullNameField=DisplayName` (text list, split at the last blank); short name from the values of `ShortNameFields=ShortName` (text list), first value without blank, `/` or `=`; `MailFileNaming=SHORTNAME` in the shipped ini. (3) **Server platform detected per server** (path form the server returns; `ServerOSDetect=1`), then `ServerOSMap`, then `ServerOS` fallback; Linux and Windows servers, also mixed; each server gets its own path form (`mail1/x.nsf` or `mail1\x.nsf`) for registration, database open and AdminP replica requests; Preflight logs the platform per server and warns when `ServerOS` is wrong; `ServerDataDirWindows`. (4) **Registration diagnostics:** every registration parameter is written to the debug log (`Registration parameters: ...`) and repeated in a failure message; Verify names the mail server, path and form tried for a missing mail file. (5) **Dry run checks more:** ID file folder writable, configured `MailTemplate` present on the home server. (6) **New `RegisterCreateMailDb=0`:** BulkReg creates the mail file itself from `MailTemplate` right after registering the user and points the Person document at it (workaround while `RegisterNewUser` stops with err 4005 *File does not exist (surname)* - cause not yet confirmed). Upgrade from 3.6.6 or 3.7.0: `DEPLOY-3.8.0.md`. **Not tested against a live Domino server.** |
| 3.7.0 | 3.7.0 | 2026-10-06 | **Customer-environment release (Domino on Linux, 5000 users, 2 mail servers, AD cn=102939ops).** (1) **Preflight batch segregation:** Preflight no longer deep-checks every user. It plans all candidates (home server, batch number, mail folders) and checks ONE batch in detail (`PreflightScope=BATCH`, `PreflightBatchNo=1`, or `ALL`); users in open batches and users without an address are excluded exactly as in Build Batch; new report `_batchplan.txt` (users per batch and server, capacity used). (2) **Automatic distribution over the home servers:** new `HomeServers`, `HomeServerMaxUsers=2500`, `HomeServerAssignment=BALANCED\|FILL`; mapping column 3 `AUTO` (or empty) takes the next server of the pool; a rule naming a server still wins; load = users already in the new mail folders + open batches + this run; ERROR when all servers are full. Previously the catch-all rule put everybody on one server. (3) **Names:** the Notes full name comes from the Person item `FullNameField=DisplayName` (text list, "First Last", split at the last blank; fallback FirstName/LastName when empty). **Short name** is read only from the values of `ShortNameFields=ShortName` (text list, AD samaccountname), never the FullName/cn; each value is examined and the first without blanks, `/` or `=` that is not First Last wins, otherwise ERROR. (4) **Internet address constructed** as `<shortname>@<InternetDomain>` when AD has none (`ConstructInternetAddress=1`, `InternetDomain`); batch column `InetSource` (AD / CONSTRUCTED); skip-and-flag applies only when it cannot be constructed. (5) **Linux and Windows servers, also mixed:** `ServerOS` (default platform) and `ServerOSMap` (per server, e.g. `DominoADMail/Demo:LINUX,DominoADMail2/Demo:WINDOWS`); the platform of each server is **detected from the server** (path form of its databases; `ServerOSDetect=1`), then `ServerOSMap`, then `ServerOS` as fallback, and Preflight logs it and warns when `ServerOS` is wrong; each server gets the path form it understands (`mail1/smith.nsf` or `mail1\smith.nsf`) for registration, database open and AdminP replica requests; `ServerDataDir` (/local/notesdata), `ServerDataDirWindows`, `ServerDataDir=/local/notesdata`, `ServerFileOwner`; mail file paths are sent to the servers as `mail1/smith.nsf` (registration, database open, AdminP replica requests); batch/audit show the server form; Preflight writes mkdir/chown commands for `/local/notesdata/mail1..N`; `MailFolderMax` default 3 (per server, 2500 users / 1000 per folder). `server_mapping.csv` catch-all is now `*;*;AUTO;;;;;`. (6) `MailFileNaming=SHORTNAME` in the shipped ini (mail file = samaccountname, e.g. `mail1/112236ops.nsf`); 03 writes every registration parameter to the debug log (`Registration parameters: ...`), repeats them in the failure message and checks that the ID file folder exists before calling RegisterNewUser. Admin Guide: revision history and settings tables only; the step-by-step procedures (B4, B11, B12, D3) still describe the earlier flow. **Not tested against a live Domino server** - see DEPLOY-3.8.0.md. |
